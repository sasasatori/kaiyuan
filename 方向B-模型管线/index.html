    方向 B：模型管线——一份配置文件怎么变成模型¶

    OpenWAM 的模型就像一盒积木。你写一份购物清单（配置文件），代码照着清单把积木拼成一个可以训练的模型。这个方向要搞懂三件事：积木有哪些、清单怎么写、拼的时候发生了什么。 前两周只需要读代码、写文档，不需要显卡、不需要装环境。

    这个方向的最终目标：学完后，你能自己拼装和扩展模型——写一份配置就能把模型组出来；需要新组件时，能照扩展指南亲手加一个。 分阶段路线：① 读代码，画出"配置怎么变成模型"的链路（B-1、B-2）→ ② 做可行性矩阵、亲手加一个新积木、审计冻结与学习率（B-3、B-4、B-6）→ ③ 接通外接视觉编码器（B-5）。

    你需要准备什么¶

    什么东西 什么时候才需要 怎么获取
    源码 + 编辑器 一开始就要 前两周零依赖，checkout 下来就能读
    CPU 开发环境 B-2、B-3、B-4、B-6 在 OpenWAM/ 下跑 pip install -e '.[dev]'，不用显卡
    DINOv3 或 FLUX.2 VAE 权重（约 0.4GB，二选一） 只有 B-5 需要 跑 python scripts/download_assets/download_visual_encoder.py；两个都要先在 HuggingFace 上申请授权，建议第二周就去申请

    平时做实验不用下载任何真权重：测试代码里自带一个假模型，拼装、冒烟都靠它。等授权的那几天用其他任务填满。

    先搞懂这几件事¶

    清单 + 电话簿。 代码里有一种"注册表"机制，可以理解成电话簿：每个积木类登记一个名字，以后按名字就能查到类。清单里写名字，组装代码就去电话簿查出对应的类造出来。模型层有三本电话簿，分别管结构、视频骨干、编码器；动作模块没有电话簿，由各个结构代码自己直接造。

    6 种结构的区别只有一个：视频和动作两路信息怎么交流。 两种（vanilla、moe）把动作直接接在视频后面，当一条长序列一起算，区别只是中间用普通前馈网络还是"混合专家"版（一组子网络里每次挑几个来算）。一种（joint_cross_attn）先把视频算完，指定某几层把中间结果抓出来，交给专门的动作模块去"看"。一种（joint_self_attn）让视频和动作各算各的，但每一层都把两边拼在一起互相看一眼，要求两边层数、头数严格一致，不一致造模型时就报错。一种（idm）分两步：先想象未来的画面，再决定动作。最后一种（tri_system）额外加一个冻结的语言模型当"顾问"——只提供理解、不指挥动作，参数永远不许训练。

    动作模块有两种用法。 长序列那族用的动作模块很简单：编码动作、编码机器人状态、解码回动作。其他结构用的是一台独立的小型 Transformer，接口多几个，由结构代码逐层驱动它。

    谁能看谁：注意力掩码的四种模式。 掩码就是一张"谁允许看谁"的座位表。想象一个课堂：视频和动作是两个同学，mutual 是互相都能抄笔记，action_sees_video 是只有动作能看视频，video_sees_action 反过来，isolated 是谁都不许看谁。第一帧（首帧）有特殊处理，不参与这套互看。

    搭桥层和外接编码器的闸门。 清单里的 bridge_layers 是一个层号列表：cross_attn 结构里它表示"视频的哪几层把结果交出去"，self_attn 和 idm 里它直接决定动作塔盖几层；写 null 时按 bridge_interval（每隔几层搭一座）自动推算。想换掉默认的视频编码器，必须把 from_scratch 设为 true；设成 false 却配了外部编码器会直接报错，因为预训练骨干第一层的通道数和原生编码器的输出维度（z_dim=48）绑死了。

    冻结和分组学习率。 冻结 = 把某些模块标记成"不训练"，清单里在框架 yaml 顶层写 freeze: 列表；代码会关掉参数的可训练标志，并让它的前向不记录梯度。冻结是整棵子树生效的：冻一个父模块，它下面的子模块全跟着冻住。训练时参数按归属分三组——视频骨干一组、动作模块一组、剩下的一组，video_lr 和 action_lr 只管自己那组，"其他"组永远用基础学习率；被冻结的参数根本不进优化器。

    任务清单¶

    整体顺序：B-1 最先做（是全组公共地基），B-2 和 B-3 可并行，B-4 依赖 B-1 的文档质量，B-6 独立，B-5 等授权到位后插入（约 2 天）。

    任务 B-1：画出"一份配置文件怎么变成模型"的全流程图¶

    • 这件事是干嘛的：方向 E 的每个消融、方向 F 的 α 配置，第一步都是把某份清单拼成模型。你画出这张图，别人照着走就不会迷路。
    • 你要准备什么：零依赖，纯阅读。
    • 具体怎么做：
    • 读 configs/train.yaml 的 defaults 段和三份框架清单，画出"命令行里写 model=dual_system model/video_backbone=wan22_ti2v_5b 会选中哪些清单文件"的选择树。
    • 跟踪结构电话簿：清单里的两个词怎么翻译成注册名、各段参数怎么合并、子配置怎么原样传下去。
    • 跟踪模型的构造过程：编码器闸门什么时候拦人、动作模块由结构自己造、几何参数（层数/头数/文本维度）怎么从视频骨干自动回填。
    • 用一张 mermaid 序列图把全链串起来，每一跳标上发生在哪个文件。
    • 做完交出什么：一篇组装链路图解（markdown）。从任意一份清单组合出发，能照图复述每一步；至少覆盖 single/dual/tri 各一条链路的差异（tri 多一步造语言顾问）。
    • 大概多久：3-4 天。

    任务 B-2：讲清 6 种模型结构的区别 + 核对掩码四种模式¶

    • 这件事是干嘛的：把上面"6 种结构"那段展开写透——每种 3-5 句大白话加一张代码位置表。掩码部分用测试把四种模式的"谁能看谁"逐格核对，这张表方向 E 做消融对照时直接要用。
    • 你要准备什么：B-1 完成；CPU 环境。
    • 具体怎么做： 
      cd OpenWAM
python -m pytest -q tests/test_mask_modes.py -v     # 先看测试断言了什么
    • 每种结构填一行表：注册名、类在哪个文件、两路信息怎么交流（一句话）、关键配置字段、动作模块用哪种。
    • 读掩码的填表逻辑，把四种模式的"动作看视频、视频看动作"两个方向（含首帧特殊处理）填成对照矩阵，和测试断言逐格核对。
    • 标注特例：idm 不理会这个开关；清单里写 mutual 但代码默认值是 action_sees_video（见"容易踩的坑"第 1 条）。
    • 做完交出什么：6 结构对照表 + 4 模式可见性矩阵 + 和测试一致的核对记录（作为 B-1 文档的一章）。
    • 大概多久：3-5 天。

    任务 B-3：做一张"哪些骨干能配哪些结构"的可行性表¶

    • 这件事是干嘛的：5 个骨干 × 6 种结构 = 30 种组合，不是每种都拼得起来。你在 CPU 上逐个试拼（骨架级，不用真权重），拼不起来的查清原因。以后方向 E 选配置、方向 F 选骨架直接查这张表。
    • 你要准备什么：B-1、B-2 完成；不需要权重。
    • 具体怎么做：
    • 写一个临时矩阵脚本：对每个组合走一遍组装路径，抓住异常并归类（用测试里的假模型注入；Cosmos 系的重依赖要等加载权重才碰，所以 CPU 上试拼是安全的）。
    • 必须验证并归因的已知约束：VACE 和外接编码器互斥；joint_self_attn 要求两边层数/头数/头维严格一致；cosmos_predict25 配 joint_cross_attn 要在命令行手工补 +model.action_backbone.num_heads=16 +model.action_backbone.attn_head_dim=64；tri_system 必须配语言模型；cosmos3_edge 的 freeze_und=false 还没实现（设了就报 NotImplementedError，标为"已知未实现"，不当 bug）。
    • 矩阵每格标 ✅ 能拼 / ❌ + 报错原文 + 原因出在哪个文件。
    • 做完交出什么：5×6 可行性矩阵，每个 ❌ 格有报错归因。
    • 大概多久：2-3 天。

    任务 B-4：动手：照官方扩展指南给框架加一个新积木（假的也行），跑通组装¶

    • 这件事是干嘛的：官方写了一篇"怎么加新组件"的指南。你照着它给框架加一个新的视频骨干（可以是最简假实现），走通"登记进电话簿 → 清单能选中 → CPU 上冒烟跑一次"全链。顺便检验你 B-1 写的文档是不是真能当施工图用。
    • 你要准备什么：B-1 完成；CPU 环境。
    • 具体怎么做：
    • 照指南写一个视频骨干子类（实现预处理/逐块计算/收尾三段接口和几何属性），用注册装饰器以 my_video 这个名字登记；可以大量借用测试里假模型的最小实现思路。
    • 新增 configs/model/video_backbone/my_video.yaml，验证命令行写 model/video_backbone=my_video 能解析到你的类。
    • CPU 冒烟：在 single_system vanilla 下拼出来，跑一次假数据前向；故意用同一个名字再登记一次，应报 "already registered"。
    • 把每个"指南没写但实际要做的事"回注到 B-1 文档。
    • 做完交出什么：最小扩展样例（脚本 + yaml）+ 指南缺口清单。
    • 大概多久：2-3 天。

    任务 B-5：搞懂"外接视觉编码器"这条线是怎么接上的（能构建出来就行，不训练）¶

    • 这件事是干嘛的：把默认的视频编码器换成 DINOv3 这类外部编码器，中间经过"闸门检查 → 造编码器 → 视频骨干重新初始化"三步。你把这条构建路径跑通，验证输出维度契约生效。只做构建和编码冒烟，训练对照是方向 E 的事。
    • 你要准备什么：B-3 完成；DINOv3 或 FLUX.2 VAE 权重已下载（约 0.4GB，要授权）；CPU 或单卡即可。
    • 具体怎么做：
    • 负例先行：from_scratch=false 配 encoder.name=dinov3 应被闸门拒绝，记录报错原文。
    • 正例：用 model.video_backbone.from_scratch=true model.video_backbone.encoder.name=dinov3 model.video_backbone.encoder.model_path=<权重目录> 构建，观察日志里编码器构建和骨干重新初始化的触发。
    • 契约核对：断言编码器输出维度不是 48（DINOv3 是 1408）、它不能解码回画面；确认对它调"生成并解码视频"会直接报错。
    • 用一帧随机图跑一次编码，记录输出张量的形状。
    • 做完交出什么：负例报错记录 + 正例构建日志（含重新初始化的证据）+ 契约断言通过记录。
    • 大概多久：2-4 天（含等授权的时间）。

    任务 B-6：查清"冻结"和"分组学习率"的实际行为¶

    • 这件事是干嘛的：训练超参归方向 C/F 配，但"哪些参数真的在训练"这条链的语义由你审计清楚。结论写成一页备忘，别人配超参时照它就不会配错。
    • 你要准备什么：B-1 完成；CPU 环境（假模型即可测）。
    • 具体怎么做：
    • 读冻结的实现，确认两个效果（关掉可训练标志 + 前向不记录梯度）和"写了不存在的名字会静默跳过"这个行为；用假模型验证：冻结视频骨干后它的参数全部不可训练。
    • 验证连带效果：冻结一个父模块会把它下面的可训练子模块一起冻住。写个小用例证明这一点，并在文档里标注"目前清单只冻结整棵子树所以不触发，但'只训投影层'这类部分微调会踩坑"。
    • 验证顾问保护：给 tri 结构的冻结列表加上 understanding_expert，应被直接报错拒绝。
    • 审计分桶：用假模型造三组参数，断言分组归属和学习率覆盖——video_lr、action_lr 只管自己那组，"其他"组永远用基础学习率，冻结参数进不了优化器。
    • 做完交出什么：4 项语义各有一条可运行的验证记录（脚本输出）+ 一页冻结/优化器语义备忘（含连带冻结陷阱和 tri 特例）。
    • 大概多久：2-3 天。

    容易踩的坑¶

    1. 清单写 mutual，代码默认值却是 action_sees_video：绕过清单直接造模型会静默换掉座位表，实验结论悄悄失真。躲法：实验记录一律以训练存档里的 config.yaml 为准。
    2. Wan 骨干一个类登记了两个名字，名字和权重路径不符只警告不报错：只改名字不改路径，会静默加载错的骨干。躲法：B-3 逐格核对名字和路径一致。
    3. 冻结父模块会连带冻住可训练的子模块：冻结是整棵子树生效，"只训投影层"这类部分微调会踩坑。躲法：B-6 用用例固化这条语义，备忘里显式警示。
    4. 语言顾问的参数不进模型存档：它以 vlm_backbone. 前缀被整体排除在外，在它上面加可训练的小层会被静默丢掉。躲法：动 tri 相关代码前先读它文件头部的注释。

    代码地图¶

    openwam/model/architectures/            ← 模型的"总装车间"：只管把零件拼起来，不实现零件本身
├── base.py                             # 所有结构的公共爹类：组装、冻结、算损失、生成视频都在这
├── registry.py                         # 结构电话簿：清单里的两个词在这翻译成具体的结构类
├── single_system/                      # 把动作接在视频后面当一条长序列的两种结构
├── dual_system/                        # 视频动作分开算的三种结构，外加逐层调度它们的驱动器
├── tri_system/                         # 再额外带一个冻结语言顾问的结构
└── utils/                              # 座位表（谁能看谁）和搭桥层推算这两个公共小工具

openwam/model/video_backbone/           ← 视频骨干：负责"看懂画面"的主力网络
├── base.py                             # 所有视频骨干都要遵守的三段式接口：预处理、逐块计算、收尾
├── registry.py + __init__.py           # 骨干电话簿，5 个内置骨干都在这里登记户口
├── wan_backbone.py + wan/              # Wan 家族骨干的实现，换编码器后的重新初始化也在这
├── cosmos_predict25_backbone.py + cosmos_predict25/   # Cosmos-Predict2.5-2B 骨干
├── cosmos3_backbone.py + cosmos3/      # Cosmos3-Edge 骨干
└── encoder/                            # 把原始视频压成小张量的编码器，默认的和外接的都在这

openwam/model/action_backbone/          ← 动作模块：两种用法（简单版/独立小网络）的接口和实现

openwam/model/vlm_backbone/             ← 语言顾问：只有 Qwen3-VL-2B 一个，造对象时就加载

configs/model/                          ← 清单目录：选哪份清单就是选哪种拼法
├── single_system.yaml / dual_system.yaml / tri_system.yaml   # 三份框架清单：冻结、座位表、搭桥层在这选
├── video_backbone/                     # 5 个骨干和 4 个编码器各自的清单
├── action_backbone/                    # 动作模块两种用法的清单
└── vlm_backbone/                       # 语言顾问的清单

openwam/train/utils/optimizer_groups.py  ← 三组学习率的分桶逻辑
assets/openwam_usage_docs/architecture-extension.md   ← 官方扩展指南，B-4 的操作手册
tests/test_openwam_trainer.py            ← 假模型的定义，做实验不用真权重就靠它
tests/test_architecture_variants.py      ← 演示怎么用假模型把各种结构拼起来
tests/test_mask_modes.py                 ← 座位表四种模式的行为断言，B-2 要逐格核对它
