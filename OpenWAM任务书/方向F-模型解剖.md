# 方向 F：模型解剖（OpenWAM-α）

> OpenWAM-α（读作 alpha）是官方训练好的成品大模型，可以直接下载来用。这个方向把它当一台买来的机器拆开看：箱子里有什么、说明书写了什么、它是按什么配方造出来的、我们怎么在它基础上继续教。
> 前两周只需要读代码写文档，不需要显卡、不需要装环境。

> **这个方向的最终目标**：学完后，给你任何一个官方训练存档，你都能独立解剖它——讲清里面有什么、按什么配方造的，并在它基础上微调出自己的模型。
> **分阶段路线**：① 开箱解剖存档、整理动作说明书（F1、F2）→ ② 审计训练配方（F3）→ ③ 微调并部署冒烟、整理家族族谱（F4–F6）。

## 你需要准备什么

| 什么东西 | 什么时候才需要 | 怎么获取 |
|---|---|---|
| 仓库源码 + 官方文档 | 一开始（做 F2、F3、F6） | 普通笔记本就够 |
| 官方基础存档（约 24.8 GB） | 做 F1 时 | 用仓库自带下载脚本（见 F1），普通电脑就能下载和解剖 |
| 4 张 80GB 级显卡 | 做 F4 时 | 提前申请算力；官方实测 2 张 H100 在第一步就爆显存 |
| 1 张 24GB 以上显卡 | 做 F5 时 | 用来起服务、跑仿真考试 |
| 磁盘 | 全程 | 每个存档约 24.8GB。只微调预留 ≥150GB；14 个存档全下载要 ≥350GB |

## 先搞懂这几件事

**α 不是一个类，是一套组合物。** 代码里搜不到一个叫 alpha 的类。α = 一组配置选择 + 一组训练好的权重 + 一套数据约定，打包成一个目录。具体是：双系统结构（视频和动作各算各的，但每层互相看一眼）+ wan22_ti2v_5b 视频骨干 + 两路信息互相可见的掩码 + 80 维统一动作约定 + min-max 归一化 + 4 个机器人数据源混合训练。全组的部署、评测、微调都在用它，所以值得把它拆清楚、写成权威文档。

**训练存档是自包含的。** 训练存档（checkpoint）= 模型权重 + 它的配置说明书。官方每个存档目录里自带：配置说明书、权重文件、分词器、归一化统计文件。所以部署只要 `bash scripts/deploy.sh <存档目录>` 一条命令，不用找原始训练配置。

**微调不用指定模型结构。** 微调时传一个存档目录就够了，不用写 `model=...`。代码会从存档的说明书里读出模型结构并原样重建。有两个"身份键"不许变：视频骨干名字和结构框架，你要改就直接拒绝启动。打个比方：模型已经上完大学（预训练），我们请家教针对具体考试补课，规矩是"不能换学生"，所以身份锁死了。

**动作为什么是 80 个数：一个通用遥控器。** 不同机器人的动作维度不一样：单臂 7 个数，双臂加灵巧手几十个。α 的做法是造一个 80 键的"通用遥控器"：每种机器人把自己的按钮映射到固定区段（比如左臂占 0–9 号键），用不到的键拿"掩码"盖住，模型就当它们不存在。输出时再按同样的映射翻译回这台机器人自己的动作。训练时往里塞、部署时往回取，代码里各有一个函数干这件事。

**采样参数和动作长度是绑死的。** 官方约定 `num_frames=33` + `video_stride=4`（一次读 33 帧、每隔 4 帧取 1 帧），产出恰好 32 步的动作序列。配置里没有单独的"动作块长度"键。这两个采样参数一改，下游等着 32 步的代码就会错位。

**α 家族有 14 个存档。** 1 个基础版（只能拿来微调，不能直接部署）+ 13 个特训版：5 个针对真机（不同型号机械臂和灵巧手），8 个针对仿真考试（LIBERO、RoboTwin 等）。想跑起来用哪个，F6 的族谱表会告诉你。

## 任务清单

### 任务 F1：开箱——把官方存档里每个文件翻明白

- 这件事是干嘛的：下载基础存档，对照"自包含"的说法逐件检查，再打开配置说明书和权重文件结构看一遍。产出一份"α 到底长什么样"的解剖报告。这是本方向的核心交付。
- 你要准备什么：约 25GB 磁盘；普通电脑即可，不需要显卡。
- 具体怎么做：
  1. 下载（选 α 家族的基础存档，非交互模式）：
     ```bash
     cd $R
     python scripts/download_assets/download_openwam_checkpoints.py \
       --family alpha --name OpenWAM-Alpha-Pretrain-Foundation-Model --yes
     ```
  2. 列出目录内容，核对是否齐全：配置说明书、`checkpoint_step_*.safetensors` 权重文件、分词器等组件、归一化统计文件。注意这个存档带 `finetune_only=True` 标记，意思是"只能拿来微调，不能直接部署"。
  3. 打开配置说明书，记录这些键的实际取值：结构框架、结构变体、掩码模式、视频骨干名字、动作维度、状态维度、归一化方式、是否启用 80 维约定。和 README 的 Quick Start 表逐项对账。
  4. 看权重文件的键结构（普通电脑能读元数据，不用真的加载权重）：
     ```bash
     python -c "
     from safetensors import safe_open
     import glob
     f = sorted(glob.glob('<ckpt_dir>/checkpoint_step_*.safetensors'))[-1]
     with safe_open(f, framework='pt') as h:
         keys = list(h.keys())
     print(len(keys)); [print(k) for k in keys if not k.startswith(('video_backbone.dit','action_backbone'))][:50]
     "
     ```
     把键按前缀分组（视频骨干 / 动作模块 / 有没有理解模块），从权重反推模型由哪几部分组成，和第 3 步的说明书互证。
- 做完交出什么：解剖报告 1 份，含三部分：① 目录清单和自包含性核对结果；② 配置说明书关键键取值表（含与宣称的对账结论）；③ 权重键前缀分组表和结构反推结论。
- 大概要多久：1-2 天（主要是下载等待）。

### 任务 F2：整理"80 维动作说明书"速查卡

- 这件事是干嘛的：官方文档写了 80 维通用遥控器的完整约定，代码里也有一套实现。你把两边对照读，产出一张一页纸的速查卡，以后组里任何人碰到动作维度问题查这张卡就行。
- 你要准备什么：什么都不用，纯阅读。
- 具体怎么做：
  1. 精读官方微调文档：样本字段规范、键位布局（左臂 0:9 + 左手 10:34、右臂 34:43 + 右手 44:68、保留 68:80）、夹爪约定（-1 闭合 / +1 张开）、时间约定（33 帧 / 步长 4 / 32 步动作）、min-max 归一化公式和 rot6d 恒等规则（rot6d = 用 6 个数表示旋转；恒等规则 = 空键位上钉一个"不旋转"的固定值）。
  2. 对照代码逐项核实：80 维双向转换、归一化与 rot6d 钉住、训练侧生成掩码、部署侧反归一化（文件见文末代码地图）。
  3. 标出文档和代码的差异或互补点。例如：归一化在塞进 80 维之前做还是之后做，钉住的区段不一样——文档那条规则在代码里是怎么体现的。
- 做完交出什么：契约速查卡 1 份（markdown，一页纸），覆盖：键位布局表、掩码语义、归一化公式、rot6d 规则、夹爪极性、时间约定、部署侧翻译义务。每条同时标注文档位置和代码文件。
- 大概要多久：1 天。

### 任务 F3：审计 α 的训练配方——宣称和代码对得上吗

- 这件事是干嘛的：README 宣称 α 在 518.5M 帧（约 6400 小时，人视角 + 机器人）数据上预训练。但仓库里的配方文件只列了 4 个机器人数据源。你要回答一个尖锐问题：这 518.5M 帧里有多少是代码能验证的？分工：数据读取机制归 [方向A-数据管线.md](方向A-数据管线.md)，你只管配方的结论。
- 你要准备什么：什么都不用，纯阅读 + 核算。做过 F2 会有帮助。
- 具体怎么做：
  1. 读预训练配方文件：里面只有 4 个机器人数据源（agibotworld / robocoin / oxe_droid / interndata_a1），采样策略是按各源窗口数比例分配。
  2. 对照宣称：人视角那部分（EgoDex / Ego4D）不在配方里。
  3. 复核"人视角数据缺口"的 5 条证据（前人已核验，你重新走一遍确认）：两个代码文件的注释里提到过人视角数据集；但数据注册表的 13 个已注册名字里没有它们；全仓库搜不到对应类的定义；测试代码显式断言这几个名字已废弃、未注册。
  4. 核算 4 个数据源各自的训练时长设置和体量（读各源配置的注释和数据读取代码的统计逻辑），估算与 518.5M 帧的差距量级。
- 做完交出什么：配方审计报告 1 份，含：① 实际 4 源和配比策略；② 宣称 vs 代码可验证部分的逐项对账（哪些帧来自未发布的人视角数据）；③ 5 条证据的复核记录；④ 明确结论："α 预训练配方不可完整复现"的边界表述。
- 大概要多久：2-3 天。

### 任务 F4：亲手微调一次 α——在 LIBERO 数据上继续教

- 这件事是干嘛的：照官方文档的路径，用基础存档热启动，在 LIBERO 仿真数据上补课，产出一个能部署的新存档。学生不换（结构锁死），只针对 LIBERO 这门考试补。
- 你要准备什么：F1 下载好的存档；LIBERO 数据（`python scripts/download_assets/download_benchmark_data.py` 一键下载）；4 张 80GB 级显卡。这是全方向唯一重资源任务，排最后。
- 具体怎么做：
  ```bash
  cd $R
  NPROC_PER_NODE=8 bash scripts/train.sh \
    dataloader=libero \
    training.finetune_ckpt_path=<foundation_ckpt_dir_path> \
    training.num_epochs=5 \
    training.output_path=<output_dir_path>
  ```
  三个注意：
  1. 输出目录参数必须用 `training.output_path`。官方文档写的参数名是另一个，但训练代码只认这个。照文档写会报错。
  2. 显卡不够 8 张时用 `NPROC_PER_NODE=4`，还爆显存就追加 `training.batch_size=8 training.offload_optimizer_device=cpu`。
  3. 不要传 `model=...`。结构身份从存档的说明书继承，传了反而会被身份检查拒绝启动。
- 做完交出什么：微调 run 记录 + 可部署存档（供 F5 或方向 D 评测用）。验收：run 从 step 0 起步、写进新目录（不覆盖基础存档）；产出目录里有最终权重、配置说明书、归一化统计文件，可以直接 `bash scripts/deploy.sh <目录>` 部署。
- 大概要多久：2-3 天（主要是训练时长）。

### 任务 F5：把微调成果部署起来，在考场上冒个烟

- 这件事是干嘛的：把存档启动成服务，接一个 LIBERO 仿真考试客户端，跑几个回合看看能不能动、成功率高不高。只验证"能力下限"，不做精确评测——精确口径归方向 D。
- 你要准备什么：1 张 24GB 以上显卡；一个可部署存档（F4 的产物，或直接下载官方微调好的 `OpenWAM-Alpha-Sim-LIBERO`）；LIBERO 客户端环境（按 `benchmarks/libero/README.md` 装）。部署流程本身归 [方向C-部署管线.md](方向C-部署管线.md)，这里只借用它的结论。
- 具体怎么做：
  1. 起服务：`bash scripts/deploy.sh <ckpt_dir_path>`。部署侧的义务：客户端要把 80 维输出翻译回本机动作维度、应用存档里保存的反归一化、保持键位映射和夹爪约定。
  2. 按 `benchmarks/libero/README.md` 起客户端，跑一个任务套的少量回合（比如 10 个）。
  3. 记录：服务启动日志、显存占用、回合成功率（只看量级，不做精确统计）。
- 做完交出什么：冒烟报告 1 份。验收：服务正常加载存档；客户端跑完 ≥10 个回合且成功率非零（官方微调存档应该有显著成功率；F4 自己微调的产物允许较低但不能是零）；报告含显存与吞吐数字。
- 大概要多久：1-2 天。

### 任务 F6：整理 α 家族 14 个成员的族谱

- 这件事是干嘛的：官方在 α 家族下挂了 14 个存档：1 个基础版 + 13 个特训版。你整理一张族谱表，让任何人都能回答"我该下载哪一个"。
- 你要准备什么：什么都不用，纯阅读。不用真把 14 个都下载（每个 24.8GB）。
- 具体怎么做：
  1. 从下载脚本的注册表提取全部条目：1 个基础版（带 `finetune_only=True` 标记）+ 13 个微调变体——真机系 5 个：Dexterous-Hand-Wuji / RoboDojo-ARX-X5 / RoboDojo-Piper / RoboDojo-Piper-X / Single-Arm-Franka；仿真系 8 个：EBench / LIBERO / RoboCasa-GR1 / RoboCasa365 / RoboDojo / RoboTwin-Clean2Random / RoboTwin-Full / VLABench。
  2. 每个条目填 4 列：名称 / 训练数据来源（从命名和数据读取约定推断，标注推断依据）/ 机器人本体和动作维度差异（对照方向 A 的 80 维映射总表，比如 Franka 单臂 vs Wuji 灵巧手）/ 适用场景（部署到真机还是仿真考试）。
  3. 标注"只能微调"的含义：基础版供微调、不要直接部署。
- 做完交出什么：族谱表 1 份，14 行，每行 4 列；全表能指导"我该下载哪个"的决策。
- 大概要多久：1 天。

推进顺序一句话：第 1 周做 F2 + F6 → F3（纯阅读），同时发起 F1 的下载；第 2 周交 F1；拿到 4 张卡后做 F4 → F5（F5 可以先下载官方 LIBERO 存档先做，不用等 F4）。

## 容易踩的坑

1. **输出目录参数名，文档和代码不一致**：官方微调文档写的参数名训练代码不认。一律用 `training.output_path=...`，并在 F4 报告里记录这个勘误。
2. **基础存档不能直接部署**：它缺少针对具体机器人的归一化和部署语境。F5 冒烟想直接部署就用官方微调好的 `OpenWAM-Alpha-Sim-LIBERO`，别用基础版。
3. **采样参数和动作长度绑死**：`num_frames=33` + `video_stride=4` 才产出下游期望的 32 步动作。微调、部署时绝不动这两个采样参数。
4. **预训练配方复现不全**：配方只有 4 个机器人源，人视角数据的读取代码没发布，各源配置里的路径全是占位符。把 F3 定位成"审计宣称"而不是"承诺复现"，主路线是下载官方存档再微调。
